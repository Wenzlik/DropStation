# DropStation 0.5.2 — Active-state dashboard + in-app bug report

## Goal

Two parallel tracks of usability work post-0.5.1:

1. **Dashboard becomes state-aware.** Today the dashboard always
   leads with "Recently completed" regardless of whether the NAS is
   actively pushing or pulling bytes. For a torrent user that's
   backwards — when something is in flight, *that* is what they
   want to glance at. The historical feed should take the top slot
   only when the NAS is idle.

2. **Bug reports move in-app.** Settings → Report a bug today opens
   GitHub. Filing requires an account, a browser context switch,
   and a free-form text area — exactly the friction profile we
   don't want when a user is already frustrated. Replace with a
   structured form that composes an email via the system mail
   composer.

No architecture rewrite. No auth / networking changes. Auth /
session / networking surfaces remain untouched (acceptance
criterion 11).

## Implementation status

Tracked on `main`. The original 0.5.2 feature batch (active-state
dashboard + in-app bug report) shipped via the `0.5.2` TestFlight
line and was carried into the current `0.5.3` release alongside
the Czech localization. Latest repo build at this checkpoint:
build `15`.

### Shipped

- ✅ **Dashboard "Active now" section.** Renders the top three
  byte-moving tasks above Recently completed when transfers are
  in flight; drops out when the NAS is idle. Each row carries an
  icon disc, title, `↓ rate · ↑ rate · ETA · 42 %` metadata, and
  a status-tinted progress sliver.
- ✅ **Seeding folded into Recently completed.** A torrent that
  finished downloading and is now seeding is "completed content"
  from the user's point of view (the file is locally available).
  Idle seeders surface in Recently completed; seeders currently
  uploading bytes surface in Active instead, so the same row
  never appears twice.
- ✅ **Hero dual-throughput.** New dedicated `↓ X · ↑ Y` line
  between the T1 focal and the state label, only when both
  directions are moving. Single-direction case stays covered by
  the focal's arrow. Upload rate no longer competes with count
  and free-disk inside the metric row.
- ✅ **File state hierarchy in TaskDetailView.** Per-file row in
  the torrent file list now renders one of three treatments:
  Skipped (faded `⊘ Skipped`, no sliver), Completed (muted ✓, no
  sliver), Downloading (thin progress sliver, quiet priority
  label). Priority text stays subtle and never competes with the
  filename.
- ✅ **Skip-aware file priority resolver.** New
  `FilePriority.from(rawPriority:wanted:)` overload — some DSM
  builds keep the file's pre-skip priority value ("normal", …)
  in `priority` even after `wanted=false`, so trusting only
  `rawPriority` produced rows that still read "Low / Normal /
  High" while the file was no longer downloading. Decoding
  `wanted: Bool?` and folding `wanted == false` to `.skip`
  matches DSM's actual server-side behaviour.
- ✅ **In-app Bug Report form.**
  `Settings → Feedback → Report a bug` now opens BugReportView.
  Required fields: Subject, Description. Optional: Steps to
  reproduce, Expected behavior, Contact email, Include
  diagnostics. Composes via `MFMailComposeViewController` with a
  `mailto:` fallback for devices where the in-app composer is
  unavailable.
- ✅ **Diagnostics (safe-only).** Optional payload includes
  app version/build, iOS version, device model identifier
  (utsname.machine), hostname, auth method label, session state
  label, capture timestamp. Explicitly excludes passwords, SID,
  cookies, OTP, tokens, sensitive logs, torrent names.
- ✅ **Suggest a feature stays on GitHub.** Public discussion
  benefits from a low-friction account-gated forum where others
  can upvote and propose alternatives — that's the right shape.
  Only the bug report — high friction, low signal in free-form
  text — moved in-app.

## Future direction — bug-report transport

Mail-composer transport is v1. v2 lands when the project has a
small server-side forwarder:

```text
App → HTTPS endpoint → email provider
```

Candidate hosts:

- Cloudflare Worker
- Vercel serverless function
- Resend / Postmark

The data layer is already shaped for this: `BugReport` is plain
data with no MFMailComposer dependency, the recipient lives in a
constant on the model (not in the view), and `composeEmailBody()`
produces a plain-text payload the future endpoint can repurpose
as JSON.

Out of scope for 0.5.2: no SMTP credentials, no embedded auth
material of any kind.
